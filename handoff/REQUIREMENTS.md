# Product and protocol requirements — owner instructions consolidated

## Nonnegotiable user requirements
Actual permissionless public Ethereum-compatible PoS research blockchain, valueless TEST ETH; anyone from any infrastructure can join without static IP, manual invitations, private LAN, mandatory centralized RPC or account login. Participants may adopt multiple roles when satisfying objective role rules. Actual service execution, resources, measurements, on-chain fees/rewards, no synthetic live outputs. Retain native PoS, no invented consensus rewards for full/archive nodes. One-command zero-config normal onboarding (role selection and wallet/security/spending authorization are legitimate interactions); automatically discover chain and contracts, peer connectivity, optional funding, install dependencies, persist services across logout/reboot, public HTTPS dashboard, sse status/dashboard/logs. No SSH port forwarding or browser overlay requirement. No mandatory shared relay; replaceable bootstrap hints, distributed RPC and independent native node option. Do not confuse RPC clients with light clients. Full/observer nodes validate, may prune, archive optional; validator standard independent installation includes synchronized EL/CL, native staking/activation/exit, local BLS key and slashing protection. Consumer/provider/monitor can be RPC-only or local full node. Native validators earn actual protocol rewards; full/archive nodes no automatic native reward. Optional infrastructure-as-service application revenue is separate.

## Latest owner requirements (verbatim substance, 2026-11-27)
- Cloud services requested by consumers and bid on by providers are implemented through their role dashboard/UI.
- Consumer resource requests include all necessary data, code, files and other uploaded inputs through UI.
- Providers execute services automatically after bidding **once awarded, accepted, funded and admitted**; bidding alone must never start an unauthorized paid workload.
- Consumers select number of monitors, check availability and committee attack-resistance conditions (interactive check; suggest feasible alternative if not enough, no silent weakening); more monitoring seats cost more.
- Number of epochs predetermined by consumer OR proposed by provider, with price consequences; exact terms accepted and committed before funding/execution.
- Providers browse all available requests in marketplace, inspect and filter them before bidding/accepting.
- Consumer selects winning provider from received bids, no minimum number of bids. Current contract requires end of bidding window; support explicit early close/award with clear rules or explain and test negotiated close deadline; no privileged selector.
- Navigable role-specific dashboard, logs, action history, assignments, committee membership/status, complete overview. Blockchain explorer with inspectable blocks, transactions, receipts, exact details, trees where actual data/proofs exist, storage/state details; reflect what the local node actually stores, none/some/all, distinguish remotely retrieved data, pruned/unavailable versus zero. All accessible roles under public permissionless network constraints.

## Concrete workflow / design defaults (proposed, not owner-specified protocol parameters)
Consumer UI: request type (compute/batch job first, then storage service and hosting/API if time; meaningful actual cloud services not mock catalog), structured SLA CPU/RAM/disk/time/correctness/availability constraints, bounded artifact upload, workload manifest + digest, choose epoch mode fixed or provider quote, required seats n + optional reserves s, fault bound b, reward per seat/epoch, fee cap, exposure budget. Show finalized roster availability, capacity, conflict exclusions, stale observation warning and estimated gas; quorum q satisfying 2q-n>b and q<=n-b, e.g. n=4 q=3 b=1; show exact risk with assumptions and conditional limitations; revalidate on-chain funding. No guaranteed independence from address count. If insufficient, propose wait/reduce seats or revise fault goal explicitly, never weaken silently. Price breakdown service fee*epochs + report reserve n*epochs*reward + separate funded standby/keeper fees + gas. All parameters integer wei, explicit consent. Bid contains provider identity, endpoint/profile/digest, price, proposed epochs or matching fixed count, actual capacity reservation, expiry, immutable terms hash. Consumer sees all bids and can pick any valid offer, not automatically cheapest, no minimum bids. Winner accepted/funded/committee confirmed before execution. Unselected bids expire/release reservations. Results/artifacts downloadable by consumer with integrity checks; on-chain status and evidence links.
Provider UI: live available host resources and reserved capacity, marketplace listing all current requests with pagination/filter, inspect public descriptors and authorized artifacts, bid/withdraw as allowed, accept negotiated terms, automatic event-driven jobs with isolated execution, status/output/metrics/logs, signed receipt and response, earnings/refunds/capacity release, explicit safe pause/resume experiments.
Monitor UI: eligibility/bond/capacity/available assignments, primary vs standby and confirmation deadlines, automatic confirmation/probe/report subject to local policy, real per-epoch measurements and evidence hashes, abstention reasons, previous committees and votes, earned/withdrawable rewards, withdrawal and exit, actual logs. No voting on own lease, duplicate vote or mid-epoch membership change. No punishment solely for uncertainty/disagreement.
Validator/full/archive/observer UI: actual node role/capabilities, peers and sync, EL/CL head/safe/finalized, local storage usage/path category (no sensitive paths public), proposer/attestation/reward/penalty/withdrawal/fee information, public validator keys/indices/stake, block/slot/epoch navigation, hashes, roots, parents, timestamps, transactions/calldata, receipts/events, gas/basefee/priority fees, withdrawals, consensus finality and canonicality. Use real eth_getProof where supported, verify Merkle Patricia proof against block state root; do not invent full tree or imply arbitrary enumeration of state; decode storage by known ABI/layout where available, clearly label raw slots and remote reads, no private keys or JWT. Archive capability accurately detected, historical block bodies != historical state.
Multi-role navigation: one node console with tabs/sections only appropriate for enabled roles, common marketplace and explorer where supported. Responsive accessible UI, searchable/paginated history, drill-down detail, actual updates, explicit source/finality/last refreshed, no hardcoded live metrics. Public read-only dashboard plus local trusted UI/wallet signing flow; no account login or password exposed to public tunnel. Uploads/privileged actions require locally authorized owner context or cryptographically authenticated narrowly scoped request; public dashboard cannot write host filesystem or execute arbitrary commands.

## Artifact and execution security
Off-chain content-addressed artifacts, on-chain commitments and service/evidence hashes only; do not put private input/code in public chain. Manifest canonicalization, hash/size/type limits, access control by lease/authorized keys, encryption in transit and at rest where needed, key distribution scoped to award; privacy cannot be guaranteed against the provider executing plaintext, disclose. Public bid metadata cannot expose secrets. Data availability separate from integrity. Reject traversal, symlinks, zip bombs, unsafe archive extraction, arbitrary host mounts/commands, SSRF and oversized uploads. Use isolated nonroot sandbox/container with CPU/memory/time/disk/PID limits, no Docker socket/host credentials, read-only root, constrained network and explicit image allowlist/digest; untrusted arbitrary user code needs stronger isolation and threat model (e.g. VM/microVM) before public enablement. Do not expose raw execution engine or shell. Fail closed for unsupported workloads; tested safe workload adapters first. Real execution starts only from verified finalized or policy-accepted canonical authorization, idempotent job IDs, durable journals, crash/reorg reconciliation, no duplicated payment/execution on replay. Avoid executing untrusted workloads in unattended coding environment.
 
## Scientific invariants
N/F/S histories: entitlement reservation/zero/fee respectively. P=L=min admissible entitlement, C=V-U, X=U-L; P+C+X=V. World soundness conditional on evidence interpretation; signed evidence is attribution not physical truth. Monotone refinement; no reversal, double credit or forced timeout payout of unresolved exposure. Admission X+max additional exposure<=budget. Separately funded report/standby/executor budgets; bilateral EIP712 residual allocation after evidence closure is consent, not proof. Native consensus distinct from monitors. Acknowledgment binding admission only under explicit policy; signed response admission semantics review before changing baseline. Failure reports require qualified negative evidence, distinguish signed wrong results from timeout/missing response, never manufacture bad evidence. All measurements live only from actual probes. V3 remains historical baseline, new deployment/version explicitly negotiated.

## Additional requirements from earlier project decisions
Capacity-backed multi-lease assignments and resource reservations; scalable global unbiased conditional sampling, strong verifiable randomness with explicit proposer/withholding assumptions, no central randomness authority, standby order fixed in original draw, no arbitrary redraw, pre-service promotion only initially, fixed quorum, no mid-epoch member change; compensation separate and budgeted, release locks safely. Analyze selective abstention, Sybil/collusion, physical independence limits. Proof-based misconduct only; no majority-conformity punishment. Native validator expansion target seven equally weighted independent operators/fault domains (ten larger experiment), not admission cap. Actual live fault tests within safe stake bounds; destructive slashing only isolated chain with separate keys. Real public testnet security limited by test ETH economics. Dynamic roles and concurrent services. Keep clean main/release after review, preserve git history and original evidence. Do not decommission dev VMs before validated release and backups.
